# 今日、誰としゃべった？

ひとことの会話を、季節の花で振り返るスマートフォン向けPWAです。HTML / CSS / Vanilla JavaScriptのみで動作し、実行時の外部ライブラリ、アプリサーバー、ログインは不要です。人物情報と日付は端末内のIndexedDBに保存します。

## 起動・ローカル開発

Node.js 20以上で、このフォルダを開いて実行します。

```sh
npm run dev
```

http://127.0.0.1:4173 を開きます。HTMLを直接ダブルクリックする `file://` ではES Modules・Service Workerが動作しないため、ローカルHTTP配信が必要です。開発サーバーはPC自身だけに接続を許可しています。

```sh
npm install
npm test
npm run build
```

`npm install` はテスト用のfake-indexeddbのみを追加します。`dist/` が配信用の静的ファイルです。任意のHTTPS静的ホスティングにこの中身を配置できます。実行時サーバーロジックはありません。Sitesの非公開プレビューにはホスト側の閲覧認証がありますが、アプリ自身には認証処理はありません。ログイン不要の一般利用にはHTTPS静的ホスティングを使用してください。

## PWA確認方法

1. HTTPSで配信したURLをiPhone Safariで開きます。PCではlocalhostも利用できます。
2. 初回の読み込み後、共有メニューから「ホーム画面に追加」を選択します。
3. 人物を登録し、複数人をタップして花の変化を確認します。
4. アプリを閉じて再度開き、記録が残ることを確認します。
5. 一度オンラインでアプリを開いてから機内モードにし、ホーム画面から起動して日付変更・記録・再起動を確認します。
6. 5人で花が完成し、6・10・15人で色だけが変わること、同じ人物の再タップで取り消されることを確認します。

本実装の自動テストは日付・花・コメント判定とIndexedDBエミュレーションです。iPhone実機でのインストール、ストレージ保持、オフライン起動は実機確認が必要です。ブラウザデータ削除やOSによる保存領域削除で記録が消える可能性があります。現時点ではバックアップ・復元はありません。

Service Workerはアプリ資産を同一バージョンでキャッシュします。更新時は `CACHE` のバージョンを上げてください。005以降は新しい資産の取得が完了するとService Workerが有効になります。画面は強制再読み込みせず、次回の起動か設定の「最新版を読み込む」で新しいコードに切り替わります。人物記録はキャッシュとは別で、更新時に消去しません。

## 使い方

- 新規利用時は11枚の基本カードを用意します。不要なものは「…」から非表示にできます。既存利用者に基本カードを勝手に追加することはありません。
- カレンダーの日付から記録します。「今日の会話」は常に端末の今日を開きます。
- 人物ボタンは選択・解除するたびに自動保存します。1人物IDにつき1日1件です。
- 1人の相手はタップで選択・解除します。複数人のカードはタップで1人、選択後に＋－で調整、カード本体の再タップで全解除します。グループの人数には個別カードで選択した人を含めません。
- 人物・設定で名前、カテゴリ、上下の並び替え、非表示・再表示ができます。削除は論理削除（非表示）です。過去日に選択済みの非表示人物は、その日の入力画面にも表示され、取り消せます。
- 利用開始日以降の0人の日は小さな双葉で表示し、否定的なメッセージは出しません。

## IndexedDB

データベース `talk-flower` / version 2（アプリ009以降）。

| ストア | 主キー | 内容 |
| --- | --- | --- |
| people | id | displayName, type, category, createdAt, sortOrder, isActive, firstTalkDate, lastTalkDate, totalTalkDays, currentMonthTalkDays, historyMonth |
| dailyLogs | id | date（端末のローカル日付 YYYY-MM-DD）, targetId, count, createdAt, recordType, personId（互換用） |
| settings | key | value。initialized, appVersion, appStartedAt, soundEnabled, starterCardsSeeded |

新規 `dailyLogs.id` は `date:targetId`（旧IDは保持）。`[date, targetId]` の複合ユニークインデックスで二重登録を防止し、人数変更は同じ行を更新、0人は削除します。date・targetIdにも検索インデックスがあります。旧personIdとそのインデックスは互換用に保持します。ログ変更と人物の履歴再集計を同一トランザクションで確定します。失敗時はロールバックします。複数タブの書き込みもIndexedDBのトランザクションにより直列化します。

`currentMonthTalkDays` は最終書き込み時点の月を `historyMonth` とともに保存するキャッシュです。コメント判定は保存済み集計値に頼らず、対象日より前のログから算出するため、月替わりや過去日の編集でも未来の履歴を参照しません。consecutiveDaysは未実装です。

保存対象は相手の名前・種類・関係カテゴリ・話した日・人数とID・時刻・並び順などの管理情報のみです。会話内容、会話時間、位置、電話番号、メール、音声、写真は取得しません。分析送信や外部API通信はありません。

## Supabaseを追加する場合

1. `db.js` の外に同期アダプターを追加し、ローカル書き込みを維持して未同期操作をキューに保存します。
2. people / dailyLogsに所有ユーザーID、更新時刻、削除フラグを追加します。クラウド側でもユーザー・日付・personIdのユニーク制約を作成します。
3. ログインとRLSでユーザーのデータを分離します。秘密鍵はクライアントに含めません。
4. 取り消しや非表示も同期するためのtombstone、競合解決、初回アップロード、通信失敗時の再試行を実装します。
5. IndexedDBのバージョンを上げ、既存データを維持するマイグレーションを追加します。

今後の候補：実機QA、バックアップ・復元、機種変更引き継ぎ、ドラッグ並び替え、より植物に近い花の意匠、年間花畑、日付ごとの花、追加演出。今回のMVPには含みません。

## 効果音（v1.1.0）

`js/sound.js` がWeb Audio APIの低めの正弦波で音を生成します。通常は0.32秒、5人目は3音が少しずつ上がる約1.2秒の開花音です。解除時は無音、6人目以降は通常音です。外部音声ファイルは使用しません。設定の「効果音 ON / OFF」は `settings.soundEnabled` に保存し、未設定時はONです。OFFにすると再生中の音も短くフェードアウトします。

iPhone向けに人物タップの同期処理内でAudioContextを作成・再開し、無音バッファを開始します。保存成功後に音を鳴らし、再生不可でも記録は継続します。実機では端末音量を調整し、Safari・ホーム画面起動・バックグラウンド復帰・オフライン・OFF設定の再起動後保持を確認してください。実機の音質・再生は未検証です。更新受信後はアプリの画面・タブをすべて閉じて開き直すと新しいキャッシュが有効になります。

## コメントの方針

会話の良し悪し・感情・相手への好意や感謝は推測しません。記録の追加、花の変化、前の記録からの間隔のみを表現します。5人目は個別履歴より「今日の花が咲きました 🌸」を優先します。6人目以降は花びらが増える表現を使いません。人物別の回数は表示しません。

## バージョン管理

アプリの連番は001から開始します。設定画面と `js/version.js` で確認できます。変更内容は `CHANGELOG.md` に記載し、完成版には `release-001` 形式のGitタグと番号付きソースZIPを残します。現在は009、次回は010です。Sites側の自動バージョン番号とは別管理です。

## 002：季節と双葉

`js/seasons.js` の12か月分の文章を編集できます。トップの説明は設定画面へ移動しました。5週の月を標準文字サイズで縦画面に収めるためにヘッダーと余白を圧縮し、花の描画サイズは維持します。6週の月、小さな表示領域、拡大文字では必要に応じて縦スクロールできます。

`settings.appStartedAt` はローカル日付のYYYY-MM-DD文字列です。初回画面の表示前に、トランザクション内で未設定の場合だけ保存します。001以前からの移行では、現存する人物の作成日・ログ作成日・記録日と今日の最も古い日付を採用します（正確な初回起動日の情報は旧版にないため推定）。情報がなければ移行日を採用します。以後の起動・記録編集では変更しません。

003以降は会話記録を優先し、1人以上なら日付にかかわらず人数に応じた花を表示します。0人の場合のみ、開始日前は空欄、開始日以降・未来日は双葉を表示します。

## 004：かんたんな人物追加

設定の「人物を追加」は候補ボタン＋名前だけの入力画面を開きます。候補のタップ・名前の追加はその場で自動保存され、続けて追加できます。「完了」で人物一覧へ戻ります。自由入力のカテゴリはその他です。カテゴリなどの詳細は人物一覧の「編集」で変更します。同名の人物は重複追加せず、非表示の場合は既存IDと記録を維持して再表示します。

## 005：更新の読み込み

10月の花は金木犀です。10/1に1人記録した場合も、未来日を理由に双葉へ戻すことはありません。旧版が残る場合は設定画面のバージョンを確認してください。005以降は「最新版を読み込む」で更新を確認し、記録を維持して再読み込みできます。旧版からの初回移行はオンラインで開いた後、アプリを閉じて開き直してください。ブラウザのデータ削除は必要ありません。端末内の実データや表示状態は開発環境から確認できません。

## 006：記録できる日付

今日と過去日は入力可能です。利用開始日前でも1人以上の記録があれば通常の花、0人なら空欄です。開始日以降の0人は双葉です。明日以降の日付はタップすると理由を表示し、入力しません。直接の日付URLとIndexedDB書き込み処理も未来日を拒否します。端末のローカル日付で判定します。旧版で作成した未来日の記録は削除せず花として保持し、その日以降に編集できます。

## 007：登録画面・3列・並び替え

初回も候補ボタンと名前入力の登録画面を使い、追加するたびに保存します。「完了」でカレンダーへ進みます。会話入力は3列です。設定の人物一覧の左のつまみを指やマウスでドラッグすると並び替えでき、離すと保存します。画面端では自動スクロールします。上下ボタンでも操作できます。並び順だけを最新の人物データに保存するため、人物名・非表示設定・過去の記録は変えません。iPhone実機のドラッグ操作は未検証です。

## 008：設定は直接ボタン画面へ

「人物・設定」を押すと、登録済み人物の3列ボタンと追加候補、名前入力が同じ画面に表示されます。登録済みの名前ボタンは編集、未登録の候補ボタンは即時追加です。各人物の下のつまみをドラッグして並び替えます。つまみにフォーカスして矢印キーでも移動できます。会話入力の3列にも同じ順序を反映します。

## 009：相手とグループ

設定は従来どおり3列カードです。1人の相手は淡いクリーム、複数人は淡い緑。種類の文字はカードに常設しません。「…」で種類・名前・非表示を設定します。名前の自由入力時のみ種類を尋ね、キャンセル時は保存しません。新規カードのtypeは選択値を使い、名前で固定しません。

人数合計は `records.js` の `totalTalkCount()` を共用します。例：妻1＋佐藤さん1＋同僚3＝5人。1日・1カードにつき1行で、groupの＋－は同じ行のcountを更新します。本文ボタンと人数操作ボタンはDOM上の兄弟で、人数操作は伝播も停止します。花は5枚のまま、6人以上で色が変化します。人数を増やした時だけ効果音、5人になった時は開花音を使用します。カードの履歴は人数でなく記録した日数を集計します。

既存typeなしカードはpersonとして移行し、全ての旧ログにtargetId（旧personId）、count=1を補います。typeのあるカードは種類を変更しません。ID、createdAt、sortOrder、isActive、settingsは保持します。移行はIndexedDBのupgradeトランザクションで行い、失敗時はロールバックします。過去に複数人記録があるカードを1人へ変更しても、過去のcountを1へ減らしません。その過去の記録はグループ表示・調整を保ち、新規日付の記録は現在の種類を使用します。既存の1人の記録は種類をグループへ変更すると、そのまま人数を増やせます。

`cards.js`：入力カードと設定カードのHTML、`records.js`：人数・種類・共通集計。`db.js`：移行、基本カードの一度だけの作成、人数変更、履歴更新。実行時ライブラリは追加していません。

初回画面だけ確認する場合は、別ブラウザでURLを開くと現在のブラウザの記録を消さずに試せます。アプリ内に全消去機能は実装していません。
